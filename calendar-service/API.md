# Calendar Service API Documentation

Base URL: `http://localhost:3001`

## Activities Endpoints

### Create Activity

**POST** `/activities`

Creates a new calendar activity with related junction table records.

**Request Body:**

```json
{
  "startDate": "2026-03-13",
  "startTime": "14:30",
  "endDate": "2026-03-13",
  "endTime": "16:00",
  "schedulingStatusId": 8,
  "schedulingConsiderations": "Room booking required",
  "title": "Ministry Event",
  "summary": "Important event description",
  "venueAddress": {
    "street": "123 Main St",
    "city": "Victoria",
    "provinceOrState": "BC",
    "country": "Canada"
  },
  "significance": "High profile event",
  "pitchComments": "Approved by director",
  "pitchStatusId": 9,
  "leadOrgId": "00000000-0000-4000-8000-000000000004",
  "commsLeadId": 8,
  "ownerId": 8,
  "isAllDay": false,
  "oicRelated": true,
  "notForLookAhead": false,
  "planningReport": true,
  "thirtySixtyNinetyReport": false,
  "isIssue": false,
  "categoryIds": [2, 5],
  "tagIds": ["00000000-0000-4000-8000-000000000105"],
  "canViewUserIds": [1, 2, 3],
  "canEditUserIds": [1]
}
```

**Response:** `201 Created`

```json
{
  "success": true,
  "data": {
    "id": 6,
    "displayId": "MIN-000006",
    "title": "Ministry Event",
    "summary": "Important event description",
    "startDate": "2026-03-13"
    // ... full activity object
  }
}
```

**Notes:**

- `id` is auto-generated by the database
- Audit fields (`createdBy`, `lastUpdatedBy`, `createdDateTime`, `lastUpdatedDateTime`) are set automatically
- Junction table records (categories, tags, permissions) are created in a single transaction

### Get All Activities

**GET** `/activities`

Retrieves all activities with optional filtering.

**Query Parameters:**
| Parameter | Type | Description |
|-----------|------|-------------|
| `title` | string | Filter by title (partial match) |
| `startDateFrom` | ISO date | Filter activities starting on or after this date |
| `startDateTo` | ISO date | Filter activities starting on or before this date |
| `endDateFrom` | ISO date | Filter activities ending on or after this date |
| `endDateTo` | ISO date | Filter activities ending on or before this date |
| `activityStatusId` | integer | Filter by activity status |
| `ministryOwnerId` | UUID | Filter by ministry owner |
| `city` | string | Filter by city (from venueAddress) |
| `isActive` | boolean | Filter by active status |
| `isIssue` | boolean | Filter by issue flag |
| `page` | integer | Page number (default: 1) |
| `limit` | integer | Items per page (default: 20, max: 100) |

**Example Request:**

```
GET /activities?startDateFrom=2026-01-01&isActive=true&page=1&limit=20
```

**Response:** `200 OK`

```json
{
  "success": true,
  "data": [
    {
      "id": 1,
      "displayId": "MIN-000001",
      "title": "Activity Title",
      "summary": "Activity description",
      "category": ["Event", "Release"],
      "tags": ["high-priority"]
      // ... full activity objects
    }
  ]
}
```

### Get Activity by ID

**GET** `/activities/:id`

Retrieves a single activity by its ID.

**URL Parameters:**

- `id` (integer, required): Activity ID

**Example Request:**

```

```

**Response:** `200 OK`

```json
{
  "success": true,
  "data": {
    "id": 1,
    "displayId": "MIN-000001",
    "title": "Activity Title"

  }
}
```

### Update Activity

**PATCH** `/activities/:id`

Updates an existing activity. Only provided fields are updated (partial update).

**URL Parameters:**

- `id` (integer, required): Activity ID

**Request Body:**

```json
{
  "title": "Updated Title",
  "summary": "Updated description",
  "categoryIds": [1, 3],
  "tagIds": ["00000000-0000-4000-8000-000000000106"]
}
```

**Response:** `200 OK`

```json
{
  "success": true,
  "data": {
    "id": 1,
    "title": "Updated Title"
    // ... updated activity object
  }
}
```

**Notes:**

- Junction table records (categories, tags, etc.) are replaced entirely if provided
- Omitted fields remain unchanged

---

### Delete Activity

**DELETE** `/activities/:id`

Soft deletes an activity by setting `isActive` to false.

**URL Parameters:**

- `id` (integer, required): Activity ID

**Response:** `200 OK`

```json
{
  "message": "Activity with id 1 has been deleted"
}
```

## Lookups Endpoints

Lookup endpoints provide reference data for dropdowns and filters.

## Error Responses

All endpoints may return the following error responses:

### 400 Bad Request

Validation failed or invalid request data.

```json
{
  "statusCode": 400,
  "message": "Validation failed",
  "errors": [
    {
      "field": "title",
      "message": "Title is required"
    }
  ]
}
```

### 404 Not Found

Resource not found.

```json
{
  "statusCode": 404,
  "message": "Activity with id 999 not found"
}
```

### 500 Internal Server Error

Server error occurred.

```json
{
  "statusCode": 500,
  "message": "Internal server error"
}
```

  } | null;
  significance: string;
  pitchComments: string;
  pitchStatusId: string;
  dateStatusId: string;
  timeStatusId: string;
  venueStatusId: string | null;
  leadOrgId: string | null;           // UUID
  leadOrgName: string | null;
  eventLeadOrgId: string | null;      // UUID
  eventLeadOrgName: string | null;
  eventLeadId: string | null;
  graphicsUserId: string | null;
